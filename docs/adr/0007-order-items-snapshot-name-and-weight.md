# 訂單項目保存品名與重量的快照

ADR 0006 讓訂單項目即時從規格與咖啡豆讀取品名與重量。結果店家修改咖啡豆名稱後，既有訂單也跟著顯示新名稱，顧客看到的不是當初買的東西（US 54、56、70）。

訂單項目改為在結帳成立訂單的同一個交易中，把咖啡豆名稱（`product_name`）與規格重量（`weight_grams`）複製到訂單項目上，與早已保存的單價（`unit_price`）一樣是下單當下的快照。顧客的訂單詳情、送往綠界的付款項目名稱（`ItemName`）都讀快照。快照取自結帳時鎖定讀到的規格，與扣庫存、決定單價讀的是同一份資料。

這取代 ADR 0006 中「訂單項目以規格顯示品名與重量」的部分。ADR 0006 否決快照的理由是「要多存一份資料，且歸還庫存保留仍需要規格存在」：多存的只有兩個欄位；歸還庫存保留確實仍需要規格，所以快照與軟刪除並用，而不是取代軟刪除。

## Considered Options

- **維持即時讀取**：不多存資料，但改名會改寫顧客的訂單紀錄。
- **規格保存版本歷史，訂單項目指向版本**：可以追溯咖啡豆目錄本身的變更，但訂單只需要下單當下的樣子；版本表會讓所有讀取現行目錄的查詢都要多一層「目前版本」的條件。

## Consequences

- `variant_id` 外鍵與規格的軟刪除不變（ADR 0006）：取消或逾期時歸還庫存保留、逾期後把訂單項目放回購物車，仍透過規格（`withTrashed`）。
- 只快照品名與重量；產地、處理法、烘焙度等其他屬性不快照，訂單只顯示品名、重量、研磨方式與單價。研磨方式本來就存在訂單項目上。
- 既有訂單項目在 migration 中以當時的規格與咖啡豆資料補上快照（包含已刪除的規格）。
- 後台訂單頁面（#15）直接讀快照。
- ADR 0006「規格的重量建立後不能修改」原本是為了保護既有訂單；有了快照後不再是這個理由，但規則暫時維持，放寬與否另行決定。
